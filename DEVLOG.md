## §4 Gotchas & hard rules
- Pages are minified onto one line — `grep -c` counts lines, not matches. Use `grep -o PATTERN FILE | wc -l` in gates.
- Editing visible FAQ text can break or desync FAQPage JSON-LD; re-validate with `python3 research/f1/verify.py` after any FAQ change.
- The jsdom test scripts under `research/` need Node + jsdom; the box has Node 20 but no jsdom (install step missing by design) — they ship for reference and run on Marko's Mac. Treat skipped jsdom runs as unverified.
- Content batches ride in `research/<batch>/`; only their `apply_build.py` writes files. Never edit a batch-managed file by hand mid-flow — the hash-guarded replacements will refuse the next run.
- The box has no browser — layout, hover and viewport-specific behaviour are `unverified` until Marko confirms with Chrome DevTools on Mac 2 (or impeccable detect with --viewport).
- `scripts/check_structure.py` enforces balanced tags through `scripts/check_markup.py` since CMB-003 — a batch whose patch drops a closing tag fails the 40/40 gate. Use `scripts/check_markup.py --text FILE` before vs after to prove which text a batch changed.
- Balanced tags can still be nested wrong. Since CMB-004 `scripts/check_markup.py` adds three structure checks — `block-in-heading`, `outside-container`, `content-in-calculator` — all run from the 40/40 gate.
- Markup and layout changes need a render check; the box has no browser, so chat renders a pushed branch. Patch whole elements, never text that runs across tag boundaries — that is how the 21 CMB-003 pages broke.
- One click binding per FAQ accordion and per mobile-menu toggle. Two bindings cancel out (one tap opens and closes) — the CMB-005 regression on 13 pages. Since CMB-005 `scripts/check_structure.py` fails any page whose FAQ or menu toggle has a click-binding count ≠ 1.
- FAQPage JSON-LD answers must equal the visible answers on the same page. `scripts/check_structure.py` enforces this since CMB-005; keep the schema in step whenever FAQ text is rewritten.
- `assets/js/calculator.js` rounds BMI once via `round1()` — categories, what-if tables and BMI Prime all come from the shown value. Healthy limits are whole units whose rounded BMI falls inside 18.5–24.9 (`weightBounds()`), the rule the BMI charts use. A page table that gives kg for an inch height labels the cm with one decimal (5'10" = 177.8 cm).
- Page dates follow git history (since CMB-009): schema `dateModified` = the last commit that changed the visible text inside `<main>`; `sitemap.xml` `lastmod` = the last commit that changed that text, its links or the JSON-LD. Removing or editing a visible date moves neither. Dataset objects keep their own `dateModified` tracking the data. Check with `python3 research/dates/date_truth.py` (exit 0 = every page agrees); run it after every batch's commit.
- Since CMB-009 `scripts/check_structure.py` fails any page whose byline shows a review/update date and any "N min read" line (D-12). Legal pages `/privacy/` and `/terms/` keep their "Last updated" line.
- Pilot branches never carry DEVLOG changes — DEVLOG commits go to `main`, so a later merge back from a pilot can't conflict on `DEVLOG.md`.
- Weight-by-height tables list the lowest to highest whole lb and whole kg whose rounded BMI falls in the category at that exact height. Each unit is worked out on its own, never converted from the other. A paired height label has one decimal (5'2" = 157.5 cm; 145 cm = 4'9.1"). Since CMB-008 `scripts/check_weight_tables.py`, run by `check_structure`, enforces range cells (`A–B`, `≤`, `≥`, `<`) in any table with a BMI-category header. Single-value cells (min/max columns) are not gate-checked — build them with `research/chart-tables/chart_rules.py`.
- Since CMB-010 `scripts/check_content_integrity.py` (imported by `check_structure.py`) fails: a call to action without a link; empty boxes / steps / table frames; cut sentences; duplicate or dead related links, or cards inside a paragraph; emoji in visible text; inline-styled button links or bylines; D-11 sex-specific ranges; placeholders in headings (`(teaser)`, TODO, TBD). Pre-CMB-010 score 5/40.
- The impeccable detector cannot see a missing link, a cut sentence, an empty box or the calculator results panel. Before every batch, chat runs the `research/site-checks/` probes (`text_probe.py`, `box_probe.py`, `ui_probe.py`, `overflow_menu.py`) and `snap_results.py` for the results-panel findings. R4 checks cover a calculator page only *before* Calculate.
- Shared component rules (DESIGN.md has the details): `.cta-button` / `.cta-button--sm` for links that act as buttons (flat `--link`, D-13); strong category shades for bars and steps that carry white text, unlabeled bars keep the base colours; category table cells use the `/bmi-chart/` tints with text tinted from the same hue; cards and FAQ items inside a section render flat (no card-in-card); no emoji or pictograph icons anywhere, including calculator results. Since CMB-011 `.related-grid` / `.related-card` is a flat link list (divided by hairlines), used by `/blog/` and `/404.html`.
- Calculator results rules (DESIGN.md "Calculator results — answer first", since CMB-011): flat tint card with the BMI number in the strong shade; sentence-case `<h2>` sections divided by hairlines (no card-in-card); right-aligned tabular numbers with the other unit sitting under each value; category colour only on dots and BMI values; the user's row gets a "You" pill (never an arrow glyph); the user's unit shows first everywhere; metric BMI is `kg/m²`, US units keep 703; no own targets, no unsourced thresholds.
- Result category names (since CMB-011) follow CDC: Healthy weight, Overweight, Class 1 / Class 2 / Class 3 obesity; WHO's Severe and Moderate thinness below BMI 17.
- Since CMB-011 `scripts/check_structure.py` runs `js_problems()` on `assets/js/calculator.js` (no emoji / arrow entities, no low-contrast hexes as text colour, no gradients).
- Since CMB-011 the content-integrity gate (`scripts/check_content_integrity.py`) also fails: numbered items that skip a number (`#2` missing between `#1` and `#3`, or `Method 2` alone); a caption for a missing table ("Rows…/Columns…" without a table, or "the table below/above" with none); empty chart rows / icons / bar tracks; headings with nothing under them.
- Since CMB-011 `check_structure` fails `/blog/` unless it links every sitemap guide and its `ItemList` and visible counts (title, meta, intro) match. A new guide must be added to the hub in the same batch.
- A gate cannot judge every leftover of a bulk deletion ("This paradox…" with the paradox gone). After any bulk-deletion commit, run `python3 research/site-checks/residue_scan.py <commit>` and read every hit — CMB-011 found 15 leftovers on 9 pages this way.
- Since CMB-012 `apply_build.py` substitutes `{TODAY}` in an edit's new text with the box's local date (the same clock `git commit` uses). Batches that write sitemap `lastmod` and schema `dateModified` use this, so `date_truth` passes on any day as long as apply and commit happen the same day. `CMB_TODAY` env var overrides it for tests only.
- US rank rule (since CMB-012, on `/` and `/men-bmi-calculator/`): "higher than X%" counts only adults with a strictly lower BMI (read the NHANES curve at BMI − 0.1); "lower than Y%" counts only those with a strictly higher one. Equal BMIs count on neither side. The old rule double-counted ties and added 0.5–1 point.
- In calculator results the converted unit shows one decimal both ways ("72 kg (158.7 lbs)", "159 lbs (72.1 kg)"), so a converted healthy limit never rounds across a category line. Applies to healthy-limit tiles, ideal-weight BMI-range tile, milestones and the weight tile.
- `.cat-dot` (DESIGN.md): the category dot used in static tables, drawn in the strong shade from the same category palette the result card uses.
- `research/home-build/home_test_playwright.py` is the homepage check (rank values, figures, widths at 320/360/390/1280, FAQ). It needs Playwright + Chromium; the box has neither, so chat or the Mac runs it.
- Since CMB-013, `apply_build.py` also substitutes `{TODAY}` in whole new/replaced files whose manifest entry has `"today": true`. The hash is of the package copy (which keeps `{TODAY}`); the written file carries the apply date. Pages ship as templates this way for schema `dateModified` and `article:modified_time`. The sitemap `lastmod` stays a `{TODAY}` edit.
- NHANES comparison rule (since CMB-013): a page states a difference between groups only when its 95% CI excludes 0 (Taylor linearisation, SDMVSTRA × SDMVPSU, 15 df). Otherwise it gives the margin of error.
